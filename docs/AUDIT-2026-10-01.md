# mockcalls audit and first test run (2026-10-01)

Scope: full read of the repo on branch `claude/optimistic-faraday-kifud9` (commits `204a846`, `e2aa894`), a headless test run in a cloud container against a throwaway Neon branch, and fixes for the high-severity findings (commit on this branch). Nothing was deployed.

## 1. What is built

- Auth and roles via Clerk (`proxy.ts`, `lib/auth.ts`); manager role read from `sessionClaims.metadata.role`.
- Call lifecycle: create (server action) → `/start` (ElevenLabs WebRTC token) → browser call (`@elevenlabs/react`) → `/end` (client transcript, ElevenLabs transcript swap, metrics, Claude scorecard) → results page (audio proxy, scorecard, metrics, key moments, transcript).
- History and analytics (rep trends, manager team view).
- `scripts/rescore.ts` maintenance CLI; 31 unit tests for metrics, analytics and score normalization.
- One `calls` table; the live Neon schema matches `db/schema.ts` exactly.
- No broken imports, dead components, TODOs or committed secrets.

Verified against live docs, not bugs: `claude-opus-5` is a valid model id (`claude-opus-5-5` is newer and cheaper), the ElevenLabs token endpoint does return `conversation_id`, and the `@elevenlabs/react` usage (provider, overrides in the hook) is correct.

### Blockers found in the environment

1. **ElevenLabs key lacks `convai_write`.** `/start` returns 502; ElevenLabs answers 401 `missing_permissions`. Create a key with Agents Platform write access.
2. **No `ANTHROPIC_API_KEY`** in the cloud environment, so every scoring run fails.
3. **Clerk session claims template not applied.** The session JWT has no `metadata` claim, so no one can be a manager. Run the `clerk config patch` from README step 3 on dev, and again on prod. Confirm the `*@outsorcy.com` allowlist too.
4. `main` already has two rows (one failed, one created) from an earlier manual attempt.

## 3. Fixed in this branch

| # | Finding | Fix |
|---|---|---|
| 1 | `rescore --claude --missing` SQL lost its parentheses and matched `created` / `in_call` rows, which `runScoring` then marked `failed` (and `/end` would have refused to save the real transcript). Confirmed live. | `and(FINISHED, or(...))` in `scripts/rescore.ts`. Verified: dry run selects only finished rows. |
| 2 | `rescore --refetch` swapped the transcript but kept the old scorecard, so key-moment `#turn-N` links pointed at the wrong turns. | Refetch now runs `runScoring` (metrics + judge). |
| 3 | A crash during scoring left a call at `ended` forever: spinner never stops, retry only accepted `failed`. | `storeMetrics` moved inside the try in `lib/run-scoring.ts`; `rescoreCall` and the results page accept `ended` rows older than `STUCK_AFTER_SECS` (90 s) and show "Scoring didn't finish, Try scoring again"; `ScoringPoller` stops after 40 polls and refreshes. Verified live. |
| 4 | `/end` was read-then-write, so a double submit ran ElevenLabs polling and Claude twice. | Single conditional `UPDATE … WHERE status = 'in_call' RETURNING`; the loser gets the current status. `rescoreCall` uses the same pattern for `failed` rows. Verified live: two concurrent `/end` calls, one scoring run. |
| 5 | `/end` holds the request open through polling plus an Opus call with default high effort. | `maxDuration = 120` on the route and the results page; `effort: "medium"` on the judge. Background scoring stays in the backlog. |
| 6 | `startSession` / `endSession` not awaited. | Awaited; WebRTC failures now reach the catch. |
| 7 | `waitForDone` aborted on the first transient error and slept once too often. | Per-attempt catch, no trailing sleep. |
| 9 | `/end` accepted a call that was never started (fabricated transcript path). | Returns 409 `this call was never started`. Verified live. |

Known limitation: two simultaneous "Try scoring again" clicks on a *stuck* (not failed) call can still both run, because there is no in-progress status to claim. Low risk; a `scoring` status would close it.

## 4. Backlog (not fixed), by severity

Medium
- 8. Audio route treats ElevenLabs 202 as success and can stream a "not ready" body as audio (`app/api/calls/[id]/audio/route.ts`).
- 10. No `beforeunload` / unmount handling; closing the tab mid-call leaves `in_call` forever and `rescore --refetch` never selects such rows. No abandon flow; history has no resume link.
- 11. `/start` allowed while already `in_call`, overwriting the conversation id.
- 12. A failed rescore leaves the old scorecard; history still shows its score next to `failed`.
- 13. `tagMeta(id)!` crashes old results pages if a tag id is ever removed from the taxonomy.
- 14. Missing ElevenLabs `time_in_call_secs` yields NaN talk seconds ("NaN:NaN").
- 15. Scoring: no refusal `fallbacks`, failure reason not stored, no prompt-injection guard for transcript text.
- 16. "You" hardcoded in `TranscriptView` and `MomentsTimeline` when a manager views a rep's call.
- 17. `AudioPlayer` can leak a blob URL on unmount.
- 18. Analytics caps "all time" at 1000 calls, history at 200, no paging; "Meetings booked" also counts `callback_agreed`.
- 19. Invalid `APP_TIMEZONE` throws and crashes history and analytics.
- Manager cannot rescore; no automatic client → ElevenLabs transcript upgrade.

Low
- `MAX_MOMENTS` can never bind; `--metrics` flag is a no-op; `--claude` silently overrides `--refetch`; bad `--limit` becomes NaN.
- `GET /api/calls/[id]` returns a scorecard nobody reads; several stored metrics are never shown.
- `personaBrief` does not say which persona is the gatekeeper although the judge prompt has gatekeeper rules; removing a persona 404s its old calls.
- Stale comments in `db/schema.ts` and `lib/scoring.ts`.
- README: step order (push before install), opener list wider than stated, `EXACT` keys must be lowercase, model not named.
- No `drizzle/` migrations folder; `APP_TIMEZONE` missing from `render.yaml`; health check proves only Clerk and the server.
- Consider `claude-opus-5-5` for the judge (cheaper, current).

## 6. Reproducing the headless run

Sign in without a browser UI: `POST https://api.clerk.com/v1/sign_in_tokens {"user_id": ...}` then open `/sign-in?__clerk_ticket=<token>` in Playwright and save the storage state. From there `page.request` can drive `/start`, `/end` and the pages with the session cookies. A live voice call still needs a real browser with a microphone.
